## Fix 1: إزالة PrismaService المكرر من Modules

**الملفات:**
- `apps/api/src/modules/audit/audit.module.ts`
- `apps/api/src/modules/users/users.module.ts`
- `apps/api/src/modules/customers/customers.module.ts`
- `apps/api/src/modules/ledger/ledger.module.ts`
- `apps/api/src/modules/runners/runners.module.ts`

**الحالة:** الـ PrismaService موجود حالياً في providers لكل module:
```typescript
providers: [AuditService, PrismaService],
```

**الخطوة:**
1. استبدل `PrismaService` من providers بـ `PrismaModule`
2. أضف `PrismaModule` إلى imports إن لم يكن موجوداً
3. تأكد أن كل module يستورد `PrismaModule` من `../../database/prisma.module.js`

**مثال:**
```typescript
// قبل
import { PrismaService } from '../../database/prisma.service.js';
providers: [AuditService, PrismaService],

// بعد
import { PrismaModule } from '../../database/prisma.module.js';
imports: [PrismaModule],
// احذف PrismaService من providers
```

## Fix 2: Prisma.DbNull بدل null في ledger.service.ts

**الملف:** `apps/api/src/modules/ledger/ledger.service.ts` (سطر 41)

**المشكلة:** عند `data.meta` الذي يكون null، يتم تمرير null عاري بدلاً من Prisma.DbNull، مما يسبب خطأ JSON في Prisma.

**الخطوة:**
1. افتح `ledger.service.ts`
2. ابحث عن المراكز التي يتم فيها كتابة `meta: null` أو `meta: data.meta ?? null`
3. استبدلها بـ `meta: data.meta ?? Prisma.DbNull`
4. تأكد من استيراد `Prisma` من `@prisma/client`

## Fix 3: معالجة خطأ P2002 في runners.service.ts

**الملف:** `apps/api/src/modules/runners/runners.service.ts` (سطر 203-209)

**المشكلة:** عند إنشاء user جديد في الtransaction، إذا كان WhatsApp مكرراً → Prisma يرمي خطأ P2002 (unique constraint) → يجب تحويله إلى ConflictException.

**الخطوة:**
1. في الـ transaction الذي يحتوي `tx.user.create`، أضف try/catch حول `tx.user.create`
2. إذا كان الخطأ `Prisma.PrismaClientKnownRequestError` code `P2002` → ارمِ `new ConflictException('This WhatsApp number is already registered')`
3. الأخطاء الأخرى تمر كهيئة عادية

## Fix 5: JwtAuthGuard يقرأ role/status من DB

3. VerifiedUserGuard و RolesGuard سيستخدمون الـ fresh principal state

## Fix 6: RefreshToken expiresAt + rotation

### 6a: تحديث schema.prisma

**الملف:** `apps/api/prisma/schema.prisma` — نموذج `RefreshToken` (سطر 98-110)

**الخطوة:**
1. أضف حقل جديد:
```prisma
expiresAt DateTime // createdAt + 90 يوم
```
2. في الـ schema، يظهر الحقل بعد `revokedAt`:
```prisma
model RefreshToken {
  id          String   @id @default(cuid())
  userId      String
  user        User     @relation(fields: [userId], references: [id])
  selector    String   @unique
  tokenHash   String
  deviceInfo  String?
  isRevoked   Boolean  @default(false)
  createdAt   DateTime @default(now())
  revokedAt   DateTime?
  expiresAt   DateTime // createdAt + 90 يوم  ← أضف هذا

  @@index([userId, isRevoked])
}
```

### 6b: تحديث auth.service.ts — refresh()

**الملف:** `apps/api/src/modules/auth/auth.service.ts` (سطر 174-177)

**قبل:**
```typescript
const token = await tx.refreshToken.findUnique({
  where: { selector, isRevoked: false },
  include: { user: true },
});
```

**بعد:**
```typescript
const token = await tx.refreshToken.findUnique({
  where: { selector, isRevoked: false, expiresAt: { gt: new Date() } },
  include: { user: true },
});
```

### 6c: تحديث auth.service.ts — إنشاء RefreshToken جديد

**الملف:** `apps/api/src/modules/auth/auth.service.ts` (سطر 203-211)

**قبل:**
```typescript
await tx.refreshToken.create({
  data: {
    userId: user.id,
    selector: newSelector,
    tokenHash: newTokenHash,
    deviceInfo: token.deviceInfo,
    isRevoked: false,
  },
});
```

**بعد:**
```typescript
const expiresAt = new Date();
expiresAt.setDate(expiresAt.getDate() + 90);

await tx.refreshToken.create({
  data: {
    userId: user.id,
    selector: newSelector,
    tokenHash: newTokenHash,
    deviceInfo: token.deviceInfo,
    isRevoked: false,
    expiresAt,
  },
});
```

### 6d: إنشاء Migration جديدة
